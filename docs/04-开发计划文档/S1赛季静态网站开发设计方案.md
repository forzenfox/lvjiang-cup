# S1 赛季静态网站 - 开发设计方案

## 1. 文档概述

### 1.1 文档目的

S1 赛季的静态网站已在 `release/demo` 分支上完成开发和验证。本文档指导完成最后的分支迁移工作：将 `release/demo` 重命名为 `release/s1`，确保构建配置适配 `/s1` 子路径部署，并与 `release/static` 部署编排分支集成。

### 1.2 适用范围

- **前端开发工程师**：验证分支迁移后的构建和部署
- **测试工程师**：验证静态网站功能完整

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| Base Path | Vite 构建配置中的 `base` 参数，决定资源引用的路径前缀 |
| 部署编排分支 | `release/static` 分支，负责拉取各赛季构建产物并统一部署到 Cloudflare Pages |

### 1.4 前置条件

- `release/demo` 分支已存在，S1 静态网站已完成开发
- Cloudflare Pages 项目 `lvjiang-cup` 已创建（见整体部署方案文档）
- `release/static` 部署编排分支已创建

## 3. 分支迁移

### 3.1 创建 release/s1 分支

```bash
# 基于已完成改造的 release/demo 创建 release/s1
git checkout -b release/s1 origin/release/demo
git push origin release/s1
```

如果 `release/demo` 仅在本地存在：

```bash
git checkout release/demo
git checkout -b release/s1
git push origin release/s1
```

### 3.2 验证 base 路径配置

确认 `release/s1` 分支的 Vite 配置正确：

```typescript
// frontend/vite.config.ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tsconfigPaths from 'vite-tsconfig-paths'

export default defineConfig({
  base: '/s1/',                    // ← 确认已设置
  build: {
    sourcemap: false,
    target: 'es2015',
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['react', 'react-dom', 'react-router-dom'],
          animation: ['framer-motion'],
          chart: ['echarts'],
          ui: ['lucide-react', '@radix-ui/react-tabs', 'sonner'],
        },
      },
    },
  },
  esbuild: {
    logOverride: { 'duplicate-attribute': 'silent' },
    drop: ['console', 'debugger'],
  },
  plugins: [react(), tsconfigPaths()],
})
```

### 3.3 构建验证

```bash
cd /workspace

# 创建 S1 工作树
git worktree add worktrees/release-s1 release/s1

# 构建
cd worktrees/release-s1
npm run build

# 预览构建产物
npx serve frontend/dist
# 访问 http://localhost:3000/s1/ 验证
```

## 4. 与 release/static 集成

### 4.1 集成流程

S1 的部署由 `release/static` 分支的 CI 工作流自动完成：

```
开发者推送 release/s1
        │
        ▼
推送到 release/static 或手动触发 workflow_dispatch
        │
        ▼
GitHub Actions 拉取 release/s1 → 构建 → 合并到 dist/s1/ → 部署到 Cloudflare Pages
```

### 4.2 部署触发方式

**方式一：推送 release/static 触发（推荐）**

```bash
git checkout release/static
git push origin release/static
```

**方式二：手动触发（无需推送）**

```
GitHub → Actions → Deploy All Seasons to Cloudflare Pages → Run workflow
```

### 4.3 验证部署

部署完成后，访问以下 URL 确认：

```
https://lvjiang-cup.pages.dev/    → 赛季导航页
https://lvjiang-cup.pages.dev/s1  → S1 赛季静态站
```

## 5. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| `release/demo` 分支 remote 不存在 | 无法创建 `release/s1` | 从本地 `release/demo` 直接创建 |
| `base: '/s1/'` 未配置或配置错误 | 资源 404 | 构建后本地 `npx serve` 预览确认 |
| `release/static` 尚未设置 Cloudflare Pages 生产分支 | 推送后不触发部署 | 先在 Cloudflare Dashboard 配置生产分支为 `release/static` |
