# S1 赛季静态网站 - 开发设计方案

## 1. 文档概述

### 1.1 文档目的

本文档指导开发团队将 `release/demo` 分支的 S1 全栈应用改造为纯静态网站，部署于 Cloudflare Pages。核心目标：移除后端依赖，将运行时 API 数据转为静态 JSON，适配 `/s1` 子路径部署。

### 1.2 适用范围

- **前端开发工程师**：数据静态化改造、路由适配、构建配置
- **后端开发工程师**：从 SQLite 导出 S1 数据为 JSON
- **测试工程师**：验证静态化后页面功能完整

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| 数据静态化 | 将原本通过 API 请求的动态数据，预导出为 JSON 文件，构建时直接引入 |
| SPA Fallback | 单页应用路由回退：`/s1/teams` 刷新时由 Cloudflare 返回 `/s1/index.html` |
| Base Path | Vite 构建配置中的 `base` 参数，决定资源引用的路径前缀 |

### 1.4 前置条件

- `release/demo` 分支已存在（S1 的全栈应用代码）
- Cloudflare Pages 项目 `lvjiang-cup` 已创建（见整体部署方案文档）
- Git 工作树（worktree）已准备就绪（见第 9 节）

## 3. 改造步骤

### 3.1 清理后端代码

```bash
# 进入 S1 工作树
cd /workspace/worktrees/release-s1

# 删除后端模块（S1 静态站不需要）
rm -rf backend
rm -rf deploy
rm -rf scripts

# 清理前端中与管理员后台相关的代码（管理后台页面无需保留）
# 保留以下前端目录结构：
# frontend/
#   ├── src/
#   │   ├── api/          → 大部分可删除，仅保留类型定义
#   │   ├── components/   → 保留展示型组件
#   │   ├── pages/
#   │   │   ├── Home.tsx  → 保留（重构为静态数据源）
#   │   │   └── admin/    → 全部删除
#   │   ├── context/      → 重构为静态数据源
#   │   ├── data/         → 新增：存放静态 JSON
#   │   └── ...
#   ├── tests/
#   │   ├── unit/         → 保留对展示组件的测试
#   │   └── e2e/          → 可删除（管理员相关 E2E）
```

### 3.2 修改 Vite 配置

```typescript
// frontend/vite.config.ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tsconfigPaths from 'vite-tsconfig-paths'

export default defineConfig({
  base: '/s1/',                             // ← 部署子路径
  build: {
    sourcemap: false,                        // ← 生产环境关闭 sourcemap
    target: 'es2015',
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['react', 'react-dom', 'react-router-dom'],
          animation: ['framer-motion'],
          chart: ['echarts'],
          ui: ['lucide-react', '@radix-ui/react-tabs', 'sonner'],
        },
      },
    },
  },
  esbuild: {
    logOverride: { 'duplicate-attribute': 'silent' },
    drop: ['console', 'debugger'],
  },
  server: {
    port: 5173,
  },
  plugins: [react(), tsconfigPaths()],
})
```

### 3.3 数据静态化

将 S1 的所有运行时 API 数据替换为静态 JSON 文件。

#### 3.3.1 导出数据

从 `develop` 分支启动后端服务，通过 API 导出 S1 数据：

```bash
# 启动后端
cd backend
npm run start:dev

# 导出各模块数据（在另一终端执行）
curl http://localhost:3000/api/teams > frontend/src/data/s1-teams.json
curl http://localhost:3000/api/streams/active > frontend/src/data/s1-stream.json
curl http://localhost:3000/api/matches > frontend/src/data/s1-matches.json
curl http://localhost:3000/api/videos > frontend/src/data/s1-videos.json
curl http://localhost:3000/api/streamers > frontend/src/data/s1-streamers.json
```

#### 3.3.2 前端数据层改造

**改造模式：API 调用 → 直接 import JSON**

```typescript
// 改造前：HomeDataContext.tsx 中的 API 调用
const fetchTeams = async () => {
  const data = await teamService.getAll()
  setTeams(data)
}

// 改造后：直接导入静态 JSON
import s1TeamsData from '../data/s1-teams.json'
import s1StreamData from '../data/s1-stream.json'
import s1MatchesData from '../data/s1-matches.json'
import s1VideosData from '../data/s1-videos.json'
import s1StreamersData from '../data/s1-streamers.json'

// 移除去重逻辑、loading 状态、错误处理
const HomeDataProvider = ({ children }) => {
  const [teams] = useState(s1TeamsData)
  const [stream] = useState(s1StreamData)
  const [matches] = useState(s1MatchesData)
  const [videos] = useState(s1VideosData)
  const [streamers] = useState(s1StreamersData)
  // ... 省略 fetch 方法和 loading 状态
}
```

### 3.4 路由改造

```typescript
// frontend/src/App.tsx
import { BrowserRouter as Router, Routes, Route } from 'react-router-dom'
import Home from './pages/Home'

function App() {
  return (
    <Router>
      <Routes>
        <Route path="/s1" element={<Home />} />
        <Route path="/s1/*" element={<Home />} />   {/* SPA fallback */}
      </Routes>
    </Router>
  )
}
```


## 6. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| JSON 数据与组件类型不匹配 | 页面渲染异常 | 导出数据后验证 `console.log` 类型结构；使用 TypeScript 类型检查 |
| `base: '/s1/'` 导致本地开发路径变化 | 本地预览 URL 变化 | 本地开发时访问 `http://localhost:5173/s1/` |
| 删除代码过多 | 误删仍需要的组件 | 分步进行：先静态化数据 → 验证页面功能 → 再清理无用代码 |
| `release/demo` 分支不存在 | 无法创建 `release/s1` | 联系运维确认分支状态；如不可用则从 `develop` 提取 S1 代码 |
