# S2 赛季静态网站 - 开发设计方案

## 1. 文档概述

### 1.1 文档目的

本文档指导开发团队基于 `master` 分支创建 S2 赛季的纯静态网站。S2 赛季数据存储在后端 SQLite 数据库中，需要提取为静态 JSON 文件后构建前端站点，部署于 Cloudflare Pages 的 `/s2` 子路径。

### 1.2 适用范围

- **前端开发工程师**：S2 静态站点组件开发、数据接入、构建配置
- **后端开发工程师**：从 SQLite 数据库导出 S2 全部数据为 JSON
- **测试工程师**：验证静态化后页面功能完整

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| 数据导出脚本 | 从后端数据库提取数据并生成 JSON 文件的 Node.js 脚本 |
| Base Path | Vite 构建配置中的 `base` 参数，决定资源引用的路径前缀 |
| SPA Fallback | 单页应用路由回退：`/s2/*` 刷新时由 Cloudflare 返回 `/s2/index.html` |
| 部署编排分支 | `release/static` 分支，负责拉取各赛季构建产物并统一部署到 Cloudflare Pages |

### 1.4 前置条件

- `master` 分支已存在，且包含 S2 赛季的完整数据
- 后端 NestJS 服务可正常启动，数据库中有 S2 赛季数据
- Cloudflare Pages 项目 `lvjiang-cup` 已创建
- `release/static` 部署编排分支已创建
- Git 工作树（worktree）已准备就绪（见第 3 节）

## 2. 架构决策

### 2.1 技术选型建议

S2 赛季可以选择以下任一架构，不受 S1 限制：

| 选型 | 适用场景 | 开发成本 |
|------|----------|----------|
| **React + Vite（推荐）** | S2 页面结构与 S1 相似，可复用已有组件 | 低 |
| Astro | 更轻量，天然零 JS，适合内容型页面 | 中 |
| 纯 HTML + CSS | 页面结构非常简单 | 低，但维护成本高 |

> **推荐采用 React + Vite**：原因是团队已有成熟组件库（战队卡片、赛程表、主播展示、视频轮播等），复用这些组件可大幅降低开发成本。

## 4. 数据导出

### 4.1 导出脚本

在 `release/s2` 分支的 `scripts/` 目录下创建数据导出脚本：

```javascript
// scripts/export-s2-data.js
// 从 SQLite 数据库导出 S2 赛季所有数据为 JSON 文件

const sqlite3 = require('sqlite3')
const path = require('path')
const fs = require('fs')

const DB_PATH = path.resolve(__dirname, '..', 'backend', 'data', 'lvjiang-cup.db')
const OUTPUT_DIR = path.resolve(__dirname, '..', 'frontend', 'src', 'data')

// 数据库表清单及其导出文件名
const TABLES = [
  { table: 'teams',              file: 's2-teams.json' },
  { table: 'team_members',       file: 's2-team-members.json' },
  { table: 'matches',            file: 's2-matches.json' },
  { table: 'match_games',        file: 's2-match-games.json' },
  { table: 'player_match_stats', file: 's2-player-stats.json' },
  { table: 'stream_info',        file: 's2-stream.json' },
  { table: 'streamers',          file: 's2-streamers.json' },
  { table: 'videos',             file: 's2-videos.json' },
]

async function exportAll() {
  if (!fs.existsSync(DB_PATH)) {
    console.error('数据库文件不存在:', DB_PATH)
    process.exit(1)
  }

  if (!fs.existsSync(OUTPUT_DIR)) {
    fs.mkdirSync(OUTPUT_DIR, { recursive: true })
  }

  const db = new sqlite3.Database(DB_PATH)

  for (const { table, file } of TABLES) {
    const rows = await new Promise((resolve, reject) => {
      db.all(`SELECT * FROM ${table}`, (err, rows) => {
        if (err) reject(err)
        else resolve(rows)
      })
    })

    const outputPath = path.join(OUTPUT_DIR, file)
    fs.writeFileSync(outputPath, JSON.stringify(rows, null, 2))
    console.log(`✅ 导出 ${table} (${rows.length} 条) → ${file}`)
  }

  db.close()
  console.log('🎉 S2 数据导出完成')
}

exportAll().catch(console.error)
```

### 4.2 执行导出

```bash
# 确保 SQLite 数据库文件存在
ls backend/data/lvjiang-cup.db

# 执行导出脚本
node scripts/export-s2-data.js

# 预期输出：
# ✅ 导出 teams (12 条) → s2-teams.json
# ✅ 导出 team_members (60 条) → s2-team-members.json
# ✅ 导出 matches (20 条) → s2-matches.json
# ✅ 导出 match_games (45 条) → s2-match-games.json
# ✅ 导出 player_match_stats (450 条) → s2-player-stats.json
# ✅ 导出 stream_info (1 条) → s2-stream.json
# ✅ 导出 streamers (8 条) → s2-streamers.json
# ✅ 导出 videos (15 条) → s2-videos.json
```

```typescript
// frontend/src/context/HomeDataContext.tsx
import React, { createContext, useContext, useState } from 'react'
import s2Teams from '../data/s2-teams.json'
import s2TeamMembers from '../data/s2-team-members.json'
import s2Matches from '../data/s2-matches.json'
import s2MatchGames from '../data/s2-match-games.json'
import s2PlayerStats from '../data/s2-player-stats.json'
import s2Videos from '../data/s2-videos.json'
import s2Streamers from '../data/s2-streamers.json'
import s2Stream from '../data/s2-stream.json'

// 数据关联：将队员挂载到对应的战队下

  ...team,
  members: s2TeamMembers.filter(m => m.team_id === team.id),

// 导出数据供页面使用
export const seasonData = {
  teams: teamsWithMembers,
  matches: s2Matches,
  matchGames: s2MatchGames,
  playerStats: s2PlayerStats,
  videos: s2Videos,
  streamers: s2Streamers,
  stream: s2Stream[0] || null,
}
```

## 10. 并行开发注意事项

| 注意项 | 说明 |
|--------|------|
| 端口冲突 | S1 和 S2 的 dev server 端口要区分（S1: 5173, S2: 5174） |
| 数据独立性 | S2 的数据导出不依赖 S1 的任何代码，互不影响 |
| 组件复用 | S2 可以直接从 S1 的分支复制公共组件，无需通过 `develop` 合并 |
| Git 工作树 | 两个工作树共用一个 `.git` 目录，commit 时需要确认当前所在工作树 |
| 部署编排 | S1 和 S2 都由 `release/static` 分支统一部署，推送或触发后 CI 自动完成 |

## 11. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 数据库文件不存在 | 无法导出数据 | 确认 `backend/data/lvjiang-cup.db` 存在 |
| JSON 数据量大 | 构建产物过大 | 仅导出 S2 赛季相关数据；使用 tree-shaking 仅打包用到的数据 |
| `base: '/s2/'` 导致资源路径问题 | 图片 404 | 确认 `public/config.js` 中的路径使用相对路径或 `/s2/` 前缀 |
| 图片存储路径 | 图片无法加载 | 将 `uploads/` 目录中的图片复制到 `frontend/public/s2/` 下 |
| `release/static` 未配置 Cloudflare Pages 生产分支 | 推送后不触发部署 | 先在 Cloudflare Dashboard 配置生产分支为 `release/static` |
